# MarkLeaf AI 可信文档助手（Windows MVP）

MarkLeaf AI 的目标不是自动代写，而是在用户负责最终内容的前提下，提供“本地资料检索、来源约束生成、人工预览、确认插入”的可信创作流程。

## 当前能力

- 从当前文档及工作区的 `.md`、`.markdown`、`.txt` 文件检索相关段落。
- 每段资料分配 `[S1]`、`[S2]` 等来源编号，并附文件路径和行号。
- 提供资料问答、有引用草稿、一致性审查和大纲整理四类任务。
- 兼容 OpenAI Chat Completions API；默认可连接 Ollama 的 `http://localhost:11434/v1`。
- 生成结果先在独立窗口预览，用户确认后才插入当前光标位置。
- API Key 只保存在当前进程内，也可以通过 `MARKLEAF_AI_API_KEY` 环境变量提供，不写入设置文件。
- 自动跳过 `.git`、`node_modules`、`bin`、`obj`、`dist` 等目录和超过 2 MB 的文本文件。

## 使用方法

1. 打开一个 Markdown 文档或工作区。
2. 选择“编辑 → MarkLeaf AI 助手”。
3. 本地 Ollama 用户保留默认 API 地址，填写已安装的模型名称；云端用户填写兼容接口地址、模型和 API Key。
4. 选择允许使用的资料范围，输入任务要求并点击“生成预览”。
5. 对照窗口底部的来源列表核查 `[S1]` 等引用，确认后再插入文档。

## 可信边界

- 当前检索为本地关键词排序，不会把整个工作区无差别发送给模型；只发送本次列出的来源片段。
- 来源编号说明模型获得了哪些资料，不代表模型输出必然正确。用户仍需核对原文。
- 工作区可能包含私密内容。使用云端模型前，应检查来源列表并遵守所在组织的数据规范。
- 产品不应被宣传为论文代写或规避 AI 检测工具。

## 后续计划

1. 将 `[S1]` 引用变成可点击、可回到原文的编辑器标记。
2. 增加逐段差异审阅与“接受/拒绝”操作，而不仅是整体预览。
3. 支持 PDF 文本抽取、向量与关键词混合检索、索引增量更新。
4. 增加引用覆盖率、资料冲突和无来源断言检测。
5. 在 Windows 稳定后，把协议和检索核心下沉到共享层，再适配 macOS 与 VS Code。
