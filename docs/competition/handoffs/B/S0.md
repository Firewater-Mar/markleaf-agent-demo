## 1. 本阶段目标与结论

B-S0 已完成对现有 AI 契约、OpenAI 兼容客户端、排版 Agent 协调器、按需加载模块、API Key 存储及相关测试的只读审计，并形成三人联调所需的 v1 契约草案。

结论是：当前 MarkLeaf 已具备“自然语言理解排版意图 → 本地排版工具执行”的基础，但它仍是**排版工作流 Agent**，还不是分工文档所要求的“基于用户选择资料生成指定章节并保留来源证据”的文档工作流 Agent。现有代码没有来源切片、任务版本、章节候选、引用校验、调用预算及真实步骤状态这组关键能力，因此不应仅通过放宽提示词直接开启正文生成。

本阶段对应分工中的 D06、D08—D11 与 O01—O04、O07—O11 的**设计和验收准备**，不宣称这些交付物已经实现。

## 3. 当前调用链

```text
右侧 Agent 面板
  ├─ 明确本地命令 ──────────────> 本地排版/导入导出工具
  └─ 其他排版自然语言要求
       └─ TypographyAiCoordinator
            └─ ITypographyAiClient
                 └─ OpenAICompatibleTypographyClient
                      └─ /chat/completions
            └─ 返回受限计划
                 └─ 本地工具执行并生成 Diff
```

关键事实：面板目前只向模型发送当前指令和少量会话摘要，不发送当前文档正文或结构。协调器提示词明确禁止生成或改写正文。因此“AI 已连接”只代表配置可用于受限排版理解，不能推导出“AI 已具备资料写作能力”。

## 4. 发现的主要缺口

1. **缺少四个跨角色对象。** 当前没有 `TaskSpec`、`SourceSlice`、`ChangeProposal`、`StepResult`，A/B/C 无法以同一事实结构联调。
2. **缺少可靠来源输入。** 没有用户选中资料的版本、行号、哈希和切片 ID；模型也无法产出可核对的来源关联。
3. **缺少本地可信校验。** 模型返回的来源 ID、目标块、动作和版本没有对应的白名单及存在性验证器。
4. **缺少有限调用预算。** 未实现每任务最多 3 次正常调用与 1 次结构修复调用，也没有预算耗尽后的保留与恢复语义。
5. **缺少真实状态来源。** 计划文本可能看起来像执行进度，但没有统一机制保证“完成”来自实际工具或写回结果。
6. **缺少取消和幂等。** 面板调用没有贯通任务级取消；迟到响应、重复确认和同一提案重复应用尚未定义。
7. **客户端结果过于扁平。** 仅返回 JSON 字符串，无法稳定记录 usage、耗时、请求 ID、平台错误及重试原因。
8. **AST 定位能力不足。** 当前块类型和位置适合排版检查，但没有跨修订稳定 `blockId`，列表、公式等结构也没有独立块语义。
9. **测试链不完整。** 现有 `TypographyAgentPlanTests` 主要验证排版意图，尚无来源缺失、来源冲突、无效引用、过期版本和取消竞态等测试。

另有一个不属于 B 修改范围的 UI 文案问题：顶部“AI 已连接”与离线检查回复中的“未连接 AI”描述的是不同执行路径，却容易被理解为连接状态矛盾。该文案与状态展示应由 C 在后续界面阶段依据真实事件统一。

## 5. v1 契约草案

接口讨论稿位于 [`docs/competition/contracts-v1.md`](../../contracts-v1.md)，当前状态为 `HISTORICAL DRAFT / NOT A UNIFIED CONTRACT`。它只作为用户审计三方实现时的 B 侧输入，不要求 A/C 按本文字段重写。主要内容包括：

- `TaskSpec`：保留用户原话、任务目标、硬约束、偏好、待确认项、目标版本和调用预算；
- `SourceSlice`：由 A 从用户明确选择的 MD/TXT 中生成，包含来源版本、行号、短原文和哈希；
- `ChangeProposal`：B 生成的候选章节或受限插入操作，带来源、要求和 AI 支持判断，不代表已写入；
- `StepResult`：由真实模型调用、用户决定和 A 的工具执行共同推进的步骤事实；
- v1 动作白名单建议仅保留 `create_new_document` 与 `insert_section_after_block`，暂不开放替换、删除、任意脚本及任意路径；
- 每任务默认 3 次正常模型调用 + 1 次结构修复调用；
- 正常、缺资料、资料冲突、无效引用、过期版本、取消六类 G0 示例。

字段最终取舍由用户审计 A/B/C 固定版本后确认。用户给出统一规范前，B 不以自己假设的字段进入后续实现。
