# MarkLeaf Agent 使用说明

MarkLeaf Agent 是以 Agent 为主界面的 Markdown 文档软件。它面向需要依据任务要求和真实资料完成正式文档的用户，包括学生、科研人员、产品团队、技术团队和项目申报人员。

## 界面

- 左侧：项目文件和资料。
- 中间：可视化 Markdown 编辑器。
- 右侧：常驻 Agent，包含“Agent”“项目上下文”“体检”三个页面。

不需要再打开单独的 AI 窗口。打开文档或文件夹后，直接在右侧输入任务即可。

## 推荐流程

1. 打开包含 Markdown 文档的项目文件夹。
2. 在“项目上下文”中导入任务要求、评分标准或公司模板。
3. 添加 Markdown、文本、Word、PDF、表格或图片资料。
4. 在“Agent”中描述一个具体任务，例如补写应用价值、查找证据或检查前后一致性。
5. 核对 Agent 的回答和来源，确认后再插入正文。
6. 在“体检”中检查要求覆盖、证据状态、结构和本地资源。
7. 导出体检报告、AI 使用说明、答辩提纲和调研工具包。

## 可信写作规则

- Agent 只发送与当前任务相关的资料片段，不默认上传整个工作区。
- 每次写入正文前都需要人工确认。
- 临时来源编号会转换为标准 Markdown 脚注，包含来源文件和行号。
- AI 建议、人工确认和导出操作会写入项目审计记录。
- 软件检查的是资料能否支持文档表达，不声称判断绝对真伪。
- 调研工具包只生成问题与记录结构，不生成或代填调研结果。

## AI 与隐私

默认配置连接本机 Ollama：

```text
API 地址：http://localhost:11434/v1
模型：qwen3:4b
```

也可以使用兼容 OpenAI Chat Completions 的服务。使用非本地地址时，软件会在发送相关资料片段前再次确认。API Key 只保留在当前应用进程中，不写入项目文件。

## 项目文件

证据项目数据保存在 `.markleaf/proof-project.json`。导出的配套材料位于 `.markleaf/exports/`，正文始终是标准 Markdown，可以继续编辑、加入 Git 或导出为 PDF 和 HTML。

## Agent 运行内核

每次正式请求都有独立的运行编号和生命周期。运行记录位于 `.markleaf/agent/`：

- `session.json`：当前工作区最近的对话上下文；
- `runs/<运行编号>/meta.json`：目标、目标文档、状态和产物；
- `message-parts.jsonl`：正文、计划、进度、工具和错误等结构化消息；
- `tool-calls.jsonl`：工具参数与执行结果。

工具按风险分级：读取工作区文本可直接执行；写入工作区、联网和代码执行必须先经用户批准；破坏性工具默认禁用。工具不能读取工作区外的路径，也不能通过链接绕过目录限制。目前正文写入继续使用“生成预览—人工确认—可撤销”的既有流程。

这些运行记录可能包含用户提示词和模型回答，默认由 `.gitignore` 排除，不应作为项目源码上传。删除 `.markleaf/agent/` 可以清除本地 Agent 会话和运行历史，不会删除正文。
